## Part 1 — 最高優先：「硬套記得的術語」轉成觸發條件 → 固定句型

### 1.1 為什麼這個優先度最高

Mock #2（`CAS` 套到跨區域 overshoot）、Mock #3（`WAIT` 套到 promoted node 的 eviction 代價）—— **同一個錯誤形狀連續出現兩場**，比單次錯誤更值得優先處理：這代表面試官問到「這個選擇/情況的後果是什麼」時，腦中沒有先檢查「我準備講的這個詞，真的解決眼前這個機制嗎」，而是先講出一個聽起來專業的詞再說。

跟 compound-question paraphrase 是同一類問題——都是「該做一個中間檢查動作，卻跳過直接輸出」。paraphrase 這次（Mock #3）第一次不經提示做到了，證明「觸發條件 → 固定句型」的訓練方式對你有效，所以今天用同一個方法處理這個新的最高優先項。

### 1.2 觸發條件

你心裡浮出一個聽起來相關的技術名詞（`CAS`、`WAIT`、`cache`、任何你背過的專有名詞），而且是在回答「這樣做的後果/代價是什麼」或「這個機制底下實際會發生什麼」這類問題時浮出的——**這正是最容易套錯的情境**，因為壓力下大腦傾向用「聽起來對的詞」代替真正推導。

### 1.3 固定動作（三步，講出來，不是默想）

在你說出那個術語**之前**，先講一句自我檢查：

> "Before I name a mechanism — let me check: does **[term]** actually address **[the specific thing just established]**, or am I just reaching for something familiar?"

然後真的花兩秒檢查：

- **[term]** 解決的問題是什麼？（一句話講出它本來的用途）
- **[the specific thing just established]** 是什麼？（複述面試官剛剛講的機制/後果，不要換詞）
- 這兩個是不是同一件事？如果不是，就直接說「不是」，然後從第一性原理重新推。

### 1.4 兩個現場案例，各講一次校正版

**Mock #2 — 跨區域 overshoot 該怎麼壓下來：**
> "Before I name a mechanism — let me check: does **CAS** actually address bounding a shared budget across three independent regional counters, or am I just reaching for something familiar?"
> → CAS 解決的是「單一儲存位置的原子更新」；這裡的問題是「三個獨立計數器怎麼共享一個全域上限」，不是同一件事。正解方向：per-region 配額 + 週期性根據實際用量動態調整配額（Day 9 debrief 已經整理過）。

**Mock #3 — promoted node 開始自己做 eviction 的代價：**
> "Before I name a mechanism — let me check: does **WAIT** actually address the cost of a promoted node suddenly starting independent eviction, or am I just reaching for something familiar?"
> → `WAIT` 解決的是「failover 時避免遺失還沒同步的寫入」；這裡的問題是「一台原本忽略 maxmemory 的 replica，promote 後突然開始強制執行自己的 eviction，會發生什麼」，不是同一件事。正解：它可能已經累積超過 maxmemory 很多，promote 那一刻要一次性補評估、可能觸發密集 eviction burst，衝擊 hot key。

### 1.5 「我不確定」跟這個習慣是同一件事的兩種表現

Day 9 debrief 已經練過「不確定就明說」（"I'm not immediately sure... let me reason through it out loud"）。今天這個習慣是它的**前置檢查版**：不是等到完全想不出東西才承認不確定,而是**每次要講出一個術語之前都先做這個檢查**——多數時候檢查完會發現詞是對的,直接講出來即可;檢查完發現不對,就直接進入「我不確定,讓我推導」模式,而不是講錯的詞再堅持。

## Part 2 — 第二優先：Virtual Node 數量 vs Physical Node 數量，徹底切開

### 2.1 混淆的根源

Mock #3 現場：算出容量需要至少 3 台、容錯需要更多 headroom，接著卻直接跳到「100 nodes，cost 是 virtual node 記憶體，mitigate 用增加 virtual node」——把兩個維度接在同一句話裡處理成同一件事。

### 2.2 正確的心智模型：兩個維度互不取代

| 維度 | 決定什麼 | 依據 | 跟另一個維度的關係 |
|---|---|---|---|
| **Physical node 數量** | 需要幾台真實機器 | 容量算式（QPS/單機上限）+ 容錯算式（掛一台後鄰居還撐得住嗎） | 決定好之後才談下一維度 |
| **Virtual node 數量（每台幾個）** | 環上負載切得多均勻、故障時負載打散到幾台鄰居 | 通常是固定值域（Toptal：小叢集 weight 10，大叢集 100~500），跟「要幾台實體機器」無關 | 在 physical node 數量已定的前提下，獨立調整 |

**一句話釘死**：「加 virtual node 從來不會讓你需要的 physical node 變少——它解決的是『既有的 N 台之間怎麼分才均勻』，不是『要幾台』。」

### 2.3 練習：把 Mock #3 的錯誤配對重講一次

「300k req/s、單機約 100k ops/s 上限 → 至少 3 台；但 3 台零容錯（掛一台鄰居直接雙倍過載），所以選 6 台（50k/台，掛一台鄰居撐到 100k，剛好頂到上限但沒超）。**這是 physical node 的決定，跟 virtual node 完全獨立**。virtual node 另外決定：這 6 台在環上各放幾個點位，讓故障時負載能打散到多台鄰居而不是全部壓給緊鄰的一台——這才是 virtual node 真正在解決的問題。」

## Part 3 — 第三優先：Cost/Mitigation 配對的「邏輯自檢」

### 3.1 問題形狀

Mock #3 的新變體：不是「只講優點不講代價」（Mock #2 舊模式），是「代價跟緩解各講了一個詞，但兩者對不上」——例如「cost 是 metadata overhead，mitigate 用 virtual node」，virtual node 根本不會降低 metadata overhead（反而會增加）。

### 3.2 固定檢查句（講完 cost + mitigation 後，內心跑一次）

> "Does my mitigation actually reduce the cost I just named — or does it address something else?"

具體做法：講完「cost 是 ___，mitigate 用 ___」之後，把 mitigation 代回 cost 那句話裡檢查因果關係是否成立。若 mitigation 講的其實是另一個問題的解法，就是配對錯了，要重講。

## Part 4 — 練習題（口說作答，練今天三個新項目）

### 題 1（練 Part 1，觸發條件遇到就要做檢查動作）
「你的 distributed cache 某個 shard 的 replica 數量從 2 降到 1，你決定用一個機制降低『master 掛掉時來不及 promote 造成的空窗』。你脫口而出想講 `Redis Sentinel`——講之前先做什麼？」

<details>
- 先講檢查句：「Before I name Sentinel — does it actually address the promotion time gap, or am I reaching for something familiar?」
- 檢查：Sentinel 解決的是「偵測 master 故障 + 自動選出並促升新 master」，這正好就是「promote 空窗」這個問題本身的機制，兩者是同一件事——**這次檢查完發現詞是對的**，可以正常講出來。這個練習的重點不是「Sentinel 錯了」，是示範「檢查完發現對的時候，正常往下講,不要因為多了檢查動作而變得畏縮」。
</details>

### 題 2（練 Part 2）
「面試官說：『你的 6 台 physical node，其中 1 台效能是其他 5 台的 2 倍，怎麼讓它分到更多流量？』這跟 virtual node 有沒有關係，還是又是一次 physical/virtual 混淆的陷阱？」

<details>
- 這次**真的**跟 virtual node 有關，不是混淆陷阱：給效能兩倍的機器兩倍的 virtual node 數量（Day 9 Part 2.4），它在環上就佔兩倍的弧長，自然分到兩倍流量。
- 跟 Mock #3 的錯誤區分：Mock #3 是「用 virtual node 回答『要幾台實體機器』」（錯，維度不對）；這題是「用 virtual node 回答『同一批機器裡怎麼依效能比例分流量』」（對，這正是 virtual node 該解決的問題）。
</details>

### 題 3（練 Part 3，compound + cost/mitigation 自檢一起練）
「(a) 你選擇每個 shard 用 async replication 而非 sync；(b) 這個選擇的代價是什麼，你怎麼緩解？」

<details>
先覆述：「兩部分：(a) 確認我選的是 async replication，(b) 這個選擇的代價跟緩解方式——對嗎？」
- (a) 選 async replication：因為 sync replication 要等所有 replica 確認才回應 client，會拖慢寫入延遲，尤其 replica 數量增加時更明顯。
- (b) cost：master 掛掉時，「已經回應 client 成功但還沒同步到任何 replica」的寫入會遺失（Day 10 Part 2.3）。mitigate：用 `WAIT` 要求至少 N 個 replica 確認才視為完成，降低（但不是消除）遺失機率。
- 自檢：`WAIT` 這次是不是又亂套了？檢查——cost 講的正是「寫入遺失」，`WAIT` 正是「降低寫入遺失機率」的機制，兩者對得上，這次用法是對的。跟 Mock #3 的錯誤對照：Mock #3 是把 `WAIT` 套到「eviction 代價」（不相關），這裡是套到「寫入遺失代價」（相關）——同一個詞，用對地方就是對的，用錯地方就是 Part 1 要抓的錯誤。
</details>
